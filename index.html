How a lookup works

  • DKIM stands for DomainKeys Identified Mail.
  • The record lives at selector._domainkey.domain.com as a TXT record.
  • Lookups use Google DNS over HTTPS.

Guide

Generate DKIM keys with OpenSSL

Generate a 2048-bit RSA key pair for DKIM:

# 1. Generate private key
openssl genrsa -out dkim-private.pem 2048

# 2. Extract public key (for DNS record)
openssl rsa -in dkim-private.pem -pubout -outform PEM 2>/dev/null | grep -v "BEGIN" | grep -v "END" | tr -d '\n' | awk '{print "p=" $0}'

# 3. Sample DKIM TXT record
v=DKIM1; k=rsa; p=MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQC4xUT9...

The public key (p= tag) goes in your DNS TXT record at: selector._domainkey.yourdomain.com

Key size recommendations

Key sizeSecurityDNS record sizeRecommendation
1024-bitWeak~180 charsAvoid, deprecated
2048-bitStrong~350 charsRecommended
3072-bitVery strong~500 charsFor high security

Note: DNS TXT records have a 512-byte limit. 4096-bit keys may exceed this limit.

DKIM best practices (2026)

  • Use 2048-bit keys minimum. 1024-bit is considered weak and may be rejected by some receivers.
  • Rotate keys every 6-12 months. Generate new keys and update DNS before expiring old ones.
  • Use multiple selectors. Maintain at least two selectors for smooth key rotation (e.g., selector1, selector2).
  • Include all required tags. v=DKIM1, p=[public key] are mandatory. Add h=sha256 for better security.
  • Publish DKIM for all sending domains. Even if you don't send much, it prevents impersonation.
  • Monitor DKIM alignment with DMARC. Use DMARC reports to ensure your DKIM is being validated.

DKIM tag reference

TagRequiredDescription
v=YesVersion, must be "DKIM1"
p=YesPublic key (base64)
k=NoKey type (rsa is default)
h=NoHash algorithms (sha256 recommended)
s=NoService type (email is default)
t=NoFlags (y=testing, s=strict)
